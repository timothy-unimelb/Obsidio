## Item A — kernel v3: chunked in-asm loop (est. +3–7%)

**Mechanism.** `pairHashHex` does ONE iteration per call: loads 64 hex bytes
per lane (VMOVDQU + PSHUFB flip), 128 rounds, epilogue byte-swaps +
hex-expands + STORES 64 ASCII bytes per lane — which the next call reloads and
re-flips. Move the loop inside the asm: the epilogue's ASCII XMM registers ARE
the next message — PSHUFB-flip them in place and jump back to the rounds.
Memory touched only at chunk entry/exit. Deletes per iteration: one Go→asm
call (~3–5ns) + 8 stores/8 loads/4 flips (~6–10ns) of a 114.1ns pair-iter.

**Register plan.** Rounds unchanged (lane A: X1–X7; lane B: X8–X13+X15; X0 WK;
X14 flip mask). Epilogue: W regs dead — emit ASCII into the W slots (A: X3–X6,
B: X10–X13); bswap32/mask0f/hexlut constants reload from RODATA per iteration
(X0/X7/X15 free then; ~1ns).

**API.** `pairHashHexN(pa, pb *[64]byte, n int)` + `hashHex1N(pa *[64]byte,
n int)`. Go loop: `for done < 49999 { n := min(stride, 49999-done);
pairHashHexN(&a,&b,n); done += n; runtime.Gosched() }`, stride =
`riskYieldMask+1` (yield cadence unchanged — it was swept and is flat).

**Steps.**
1. Extend `benchmarks/gen2lane.py`: wrap round+epilogue emitters in a loop
   label; back-edge = PSHUFB-flip of ASCII W-slots into message quads; DECQ/JNZ
   on the count register. Keep existing single-shot routines — N variants are
   additions.
2. Regenerate `app/sha256block2_amd64.s`; copy the generator into
   `benchmarks/gen2lane.py` (it is committed evidence).
3. `shakernel_amd64.go`: declarations; self-test comparing N∈{1,2,3,17,256}
   chained against the single-shot routine composed N times (128 random starts
   each); enable `riskPairIterN`/`riskIter1N` function vars only on pass;
   `RISK_KERNEL_V3=off` keeps the v2 path.
4. `riskChain`/`riskChainPair` in main.go use the N variants when non-nil.
5. Dev box: gofmt/vet, full `-race` suite, differential walls green.
6. Tier-0 on dev box: new `BenchmarkPairFusedN` vs `BenchmarkPairFused`
   (target ≤ ~105ns/pair-iter from 114.1) and `BenchmarkSingleFusedN`.
7. `/smoke` against a capped container on the dev box.
8. Bracket `kernelv3-x86-01`. Keep if ≥ +1% and bars green; else set the kill
   switch default to off, record the negative result, move on.

## Item B — raw-TCP HTTP/1.1 fast path (est. +3–6%)

**Mechanism.** ~8% of the 2-CPU budget is net/http machinery (~15–20µs/request:
header map allocs, URL parse, ResponseWriter bookkeeping). A hand-rolled
HTTP/1.1 loop for this fixed four-endpoint contract runs ~3–5µs. The reclaimed
CPU feeds the hash workers — the win is CPU share, not latency.

**Design (correctness-first).**
1. New `app/rawserver.go`: `net.Listen(":8080")` + goroutine per connection.
   - Parse: per-conn 4KB buffer; read until `\r\n\r\n`; byte-scan method,
     path, query (no allocs on fast path); headers skipped except
     `Content-Length` (POST) and `Connection: close`. Handle split reads
     across buffer boundaries and multiple pipelined requests per read.
   - REUSE the existing handlers (`handlePrice`/`handleStats`/`handleRisk`/
     `handlePricePost`/health) through a minimal ResponseWriter adapter
     (status + body + Content-Type) so endpoint behavior, WAL, governor
     accounting (`writeJSON` counters) stay bit-identical.
   - Responses: single buffered write of precomputed header block + body;
     keep-alive default; close on parse error or `Connection: close`;
     unknown path → the contract 404 JSON shape.
   - POST /price: read exactly Content-Length bytes, then existing WAL path.
   - `SetReadDeadline` ~10s, mirroring today's timeouts.
2. Kill switch: `RISK_HTTP=std` boots the current net/http server unchanged
   (main() picks by env; default = raw). Ship-day insurance.
3. Tests: parser unit tests (split reads, pipelining, oversized header →
   close, empty/encoded query, unknown path 404); `/smoke` against BOTH
   servers; WAL durability re-run (compose up → POST → `docker kill` →
   restart → read back); full `-race` suite.
4. Bracket `rawhttp-x86-01` (champion = Item-A keeper or prior HEAD). Keep if
   ≥ +1%, bars green, and k6-visible errors ≈ internal budget − skew (the
   governor's accounting must be unchanged).
5. If kept, revalidate the three regimes where a hand-rolled server could
   diverge from net/http: co-located k6 (run k6 in docker ON the target
   against 127.0.0.1), 400-VU overdrive (`k6/overdrive.js` from the load
   box), slow-box simulation (`RISK_KERNEL=off` + `GODEBUG=cpu.sha=off`
   grading run; baseline to beat: 812,074 / 4 bars).

## Item C — AVX-512 multi-buffer insurance kernel for no-SHA-NI graders (conditional ≈ +80–150% there, 0% on SHA-NI boxes)

**Why.** Everything kernel-side is SHA-NI-gated. Pre-Ice-Lake Intel Xeons
(Skylake-SP/Cascade Lake — plausible "powerful home-lab workstation") lack
SHA-NI but HAVE AVX-512. Current fallback there: direct 2-block AVX2 kernel
(~292ns/iter) — grading simulation scores 812k with all bars green (safe, but
a big score haircut). A 16-lane AVX-512 multi-buffer kernel hashes 16
independent chains per core at ~2–3× the aggregate rate.

**Source.** Vendor from minio/sha256-simd (Apache-2.0 — keep license header +
attribution; the write-up must disclose vendoring): their AVX-512 16-lane
server implementation (`sha256blockAvx512_amd64.s` + the message-scheduling
Go shims). Gate: `!sha_ni && avx512f && avx512dq && avx512bw && avx512vl`
(mirror minio's own required-feature set from their cpuid checks) — read from
`/proc/cpuinfo` like the existing gates in `shakernel_amd64.go`.

**Dispatcher integration.** The worker model already pops up to 2 waiters;
add a lane-16 mode: when the AVX-512 kernel is active, a worker pops up to 16
live waiters (`riskTakeWork(16)`) and advances all their chains in lockstep
through the multi-buffer core; chains are all exactly 50k iterations so
lockstep is exact. Partial batches are the economics risk: a k-of-16 batch
runs at ~k/16 efficiency, so use multi-buffer ONLY when ≥8 waiters pop
(else fall back to the AVX2 single path for that batch). Hex encoding stays
`hexEncode64` per lane (packed table — portable). Yield every
`riskYieldMask+1` lockstep iterations.

**Testing without a no-SHA-NI machine.** c7i HAS AVX-512, so the code path
runs on the existing boxes: add `RISK_KERNEL=avx512` env to force the gate
(test/bench only — the shipped gate stays `!sha_ni && …`). Walls: 50k-case
differential per lane vs crypto/sha256, cross-lane leak test (16 distinct
inputs), full-chain reference, boot self-test before enable, race hammer with
the 16-lane worker. Validation runs on the testbed, all with
`RISK_KERNEL=avx512` forced + `GODEBUG=cpu.sha=off` (so stdlib comparisons are
honest): Tier-0 aggregate chains/sec vs the AVX2 path, then a full grading.js
run vs the 812k baseline — keep if ≥ +30% in that regime with 4/4 bars; also
verify a plain SHA-NI grading run is unchanged (gate must not fire there).

**Go/no-go.** This is 1–2 days of work. If the submission deadline pressure
makes it unfinishable WITH its full walls, ship without it — the AVX2
fallback is already bar-safe. Never ship a partially-tested kernel: the gate
+ boot self-test must make the worst case "falls back, loses nothing".
